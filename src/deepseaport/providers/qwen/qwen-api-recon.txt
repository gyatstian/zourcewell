# Qwen Chat Web Frontend API Recon Report

**Scope / method:** Live browser (headless) at `chat.qwen.ai` + WebFetch/grep of the served JS bundle `js/main.js` (v0.2.91, 1.8 MB, saved & regexed) + same-origin `fetch()` probes from page context with cookies (`credentials:'include'`). No credentials used, no files written.

**TL;DR:** The SPA is double-gated: a device-support gate (“Current System does not Support”) blocks SPA boot in this environment, and chat-mutation endpoints sit behind Aliyun WAF anti-bot (`AliyunCaptcha`). Read/model/config endpoints are open. There is an anonymous/guest mode (`enable_anonymous:true`).

---

## 1. URLs

- `https://chat.qwen.ai/`
  - Serves splash/download page, no redirect.
  - If a real browser boots the SPA: `/` = home/guest chat.
  - Unauthenticated + non-`/` path → SPA redirects to `/auth`.
  - JS-grep router: `if(!e){...} if(m.pathname.length>=36&&!S) h("/c/guest") else h("/auth")`.

- `https://chat.qwen.ai/auth`
  - Same splash HTML, no separate app.
  - Confirms `/auth` is the login route: `routeTologin(){Cl("/auth")}` in JS-grep.

- In headless env, both show block page: **Current System does not Support** (device-gate; no XHR traffic ever fires).
  - SPA boot therefore unobserved — most runtime shapes below are JS-grep + direct-probe evidence.

- JS bundle base:
  - `assets.alicdn.com/g/qwenweb/qwen-chat-fe/0.2.91/js/main.js`
  - Module-preloads `react-vendor.js`, `index*.js`, etc. — all same CDN dir.

No token-bearing key unauthenticated.

`localStorage.token` is **the** auth token store (JS-grep):

```js
localStorage.setItem("token", n.user.token);
```

- Set from user payload `user.token`.
- Cleared on logout via `localStorage.removeItem("token")` (+ settings, locale).
- Value shape: raw string (Bearer token), not JSON/JWT-object — consumed as `Bearer ${localStorage.getItem("token")}`.
- Reported shape unverified without login (no `.`-count JWT confirmed).

## 4. API Endpoints

**Base:** All app API lives on origin `chat.qwen.ai`.

Constants in JS-grep:

- `dt = "/api/v1"` (FastAPI-style + WS base)
- `ut = "/api/v2"`
- `ct = ""`
- Axios/fetch default base = `pn = "/api/v2"` (join: `` `${pn}${path}` ``, `withCredentials:true`).

No `/v1/chat/completions`-style legacy in use; old unversioned `/api/chat/*` routes mostly dead.

## 4b. Request Headers

JS-grep interceptor:

- `Content-Type: application/json`
- `Version: 0.2.91`
- `source: web|h5|desktop` (by UA)
- `X-Request-Id: <uuid>` (generated each req)
- `Timezone: <tz string>`
- `Authorization: Bearer token` only for non-web/h5 (desktop) — web intentionally deletes it:
  ```js
  ["web","h5"].includes(s) && n.has("Authorization") && n.delete("Authorization")
  ```
  i.e. web session rides on `acw_tc`/cookies.
- `Accept-Language: {locale},{lang};q=0.9`

## 5. SSE Stream Parsing

JS-grep of stream client:

- `fetch` stream → `TextDecoderStream` → SSE `TransformStream` (events = `{data, ...}`); chunk objects parsed w/ `JSON.parse`.
- Event envelope is OpenAI-style; handlers keyed on top-level fields:
  - `{"response.created":{response_id, response_index, chat_id, parent_id}}` → start of turn
  - `{"response.stopped":{response_id}}` → done
  - `{"response.info":{response_id, action:"skip_think"}}`
  - `{"choices":[{"delta":{content, phase, role, status, extra, lang_code, function_call:{name}, function_id, name, mcp_name}}], "usage", "response_id", "timestamp"}`
    - `phase` values incl. `answer`, `think`, `tool_call`, `KeepAlive`, `think_summary`
  - top-level `{error:{...}}` or `{sources}`, `{selected_model_id}`, `{phase, value}` (tool output), `{done:true}` terminal line.
- Stream terminator lines: plaintext `data: [DONE]` also handled (JS-grep `le.startsWith("[DONE]")`).
- `stream_options:{include_usage:true}` when model advertises usage capability.

## 7. WAF / Challenge

- Aliyun WAF anti-bot on mutating chat endpoints.
- Direct probe to:
  - `POST /api/v2/chat/completions`
  - `GET /api/v2/chat/completions*`
  - `POST /api/v2/chats/new`
- Returns HTTP 200 + HTML challenge (15,886 bytes) with:
  - `<meta name="aliyun_waf_aa" content="ff926c7f07e45e2e487a29a6197d3460">` / `..._bb ...`
  - Loads `https://o.alicdn.com/captcha-frontend/aliyunCaptcha/AliyunCaptcha.js`
  - Calls `initAliyunCaptcha({server: captchaEndpoint[]})`, `verifyType:"1.0"`
  - Captcha UI `.nc-container` (Aliyun NoCaptcha / `nc_*` keys)
  - Then auto-POSTs back to the challenged URL with `u_aref`/`u_asig`/`u_atoken` payloads.
- App also ships Alibaba risk SDK access: `window.baxiaCommon` / `__baxia__` with `checkApiPath` on whitelist `fh` (includes the chat endpoints) → triggers `BaxiaCaptchaModal` in-app.
- Read endpoints (`/api/v2/models/`, `/api/v2/configs/`, `/api/v2/auths/`, `/api/v1/auths/`) are **not** challenge-gated.
- No `cf_*` / `aws-waf-token` / Turnstile observed. `acw_tc` (httpOnly) is the Alibaba WAF edge cookie.
