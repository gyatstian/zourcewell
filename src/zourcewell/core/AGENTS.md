# core

## Purpose

Mechanics every provider shares: the retry driver, the cross-account failover
loop, the stream bridge, HTTP transport handling, OpenAI response shaping, the
provider registry, and the browser bridges. Nothing here knows about DeepSeek,
Qwen or opencode.

## Ownership

- `engine.py`: retry driver (`drive_retries`), recovery containment (`_run_recovery`), account-slot release/acquire failover (`consume_slot_abandoned`), cancellation checks, producer-thread to consumer bridge (`stream_producer` plus its `new_producer_context` / `consume_stream` ends), the shared classification tuples (`TRANSIENT_OVERLOAD_MARKERS` / `RATE_LIMIT_MARKERS` / `UPSTREAM_INVALID_MARKERS`), `new_stream_context`, `LiveEmitTracker` / `live_emit_pair` / `live_retry_predicate` (the partial-emit guard), `sse_error_frame`, `scrub_upstream_text`, `current_cancel_event`.
- `transport.py`: HTTP-level concerns only: content-type checks, `.text` vs body, error drains, caps, `http_error_code`, plus the hoisted bounded-read machinery (`_cancellable`, `_BoundedQueue`, `_abandon`, `_ClientGone`, `_READ_SLICE_SECONDS`) both web providers install on a completion response, so every read is bounded -- the SSE pump and the non-SSE body drain alike.
- `openai.py`: OpenAI response shaping shared by all web2api providers.
- `pools.py`: pure functions over `Settings` deciding which providers are active and which accounts belong to one.
- `provider.py`: the `Provider` ABC and `ModelSpec`.
- `registry.py`: lazy discovery of built-in provider modules.
- `tokens.py`: `userToken` extraction and normalization.
- `obscura_bridge.py`: WAF-cleared cookies plus browser User-Agent for the hot path; `_repo_root()` defers to `config._app_dir()` (repo root, per-user dir, exe dir) so the bridge and `config.json` share one base.
- `mcp_client.py`: small thread-safe stdio JSON-RPC client for Obscura's MCP server.
- `browser_paths.py`: discovers a real Chromium-family binary for login automation.
- `types.py`: `StreamEvent` and other shared structural types.

`tools/` is a child doc.

## Local Contracts

- `engine.py` imports no provider module and no `zourcewell.server`. Providers hand it small adapters (predicates, recover callbacks, run-once closures); it owns only the generic mechanics.
- Retry order is pow, session, token, waf, overload, one `max_retries`-bounded pass per kind.
- Error classification is one vocabulary, composed per provider: `TRANSIENT_OVERLOAD_MARKERS` / `RATE_LIMIT_MARKERS` / `UPSTREAM_INVALID_MARKERS` are the neutral tuples, and a provider writes `_engine.X + (its own extras)` while keeping its own check ORDER (rate-limit before overload wherever a throttle body also says "try again"). `transport.http_error_code` renders every non-200 as `HTTP_<status>: <body>`, so a bare status shape must classify identically everywhere -- never fork a word list or a numeric fallback back into a provider classifier.
- `engine.stream_producer` is the one `_stream_completion` skeleton: context allocation, watchdog sized `buffered=not live`, the producer exception ladder (scrub tail included), the bounded `_STREAM_EXECUTOR.submit` with its raw-thread fallback, and the `consume_stream` tail. A provider's `_stream_completion` stays a thin delegate closing over its own module-level timeout/grace globals -- both are read at generator-body time so tests can patch them per module. Never re-inline the skeleton into a provider.
- **No retry row may fire after a partial live emit.** `LiveEmitTracker` is wrapped onto the live callbacks once per attempt by `live_emit_pair`, and every provider's `_retryable(kind)` is a one-line delegate to `engine.live_retry_predicate`, which ANDs `not tracker.emitted` -- all three tables, not just the overload row, which is where the guard used to sit. Live mode `_put`s deltas as they arrive, `drain_attempt` makes content-then-error a legal ordering, and the completion POST is NOT idempotent (the upstream already appended a turn): re-POSTing it and re-streaming from delta 0 duplicates text, or interleaves two halves of one `tool_calls` JSON object, inside a 200 stream that still ends in a clean `[DONE]`. A new row that does not go through `_retryable` reintroduces exactly that.
- `_run_recovery` contains any exception a recovery step raises, logs the SCRUBBED reason at warning, and deliberately drops `exc_info`: `traceback.print_exception` reprints the exception message at the bottom, and that message is very often a raw slice of the upstream body -- the traceback was a second unscrubbed copy. Only `HTTPException` and the cancellation sentinel propagate: those are decisions, not malfunctions. A failed recovery must never turn a retryable error into a 500.
- `http_error_code(status_code, forbidden=...)` takes the provider's 403 table as an argument. Omitting it keeps the DeepSeek default, where a 403 is the AWS WAF challenge. Qwen passes an empty table so its 403 stays a real authorization failure. Never hardcode one shared mapping.
- A bare 401 is `INVALID_TOKEN`, never `BAN`. An account is marked banned only on real ban evidence.
- `scrub_upstream_text` runs on every path that can echo an upstream body, and always before any truncation: truncating first can cut a credential mid-token. The sinks to re-check when you add one:
  - `sse_error_frame` -- every outbound SSE error frame, including the locally raised watchdog timeout and generic consumer failures.
  - `transport.log_http_error` -- every non-200, so it fires on the request that is carrying the account's bearer token.
  - `_run_recovery`, and the terminal raisers: `raise_upstream_invalid` / `raise_upstream` scrub into both a `logger.warning` and the `HTTPException` detail, `raise_rate_limit` / `raise_overload` into the detail only (neither logs).
  - `ban_403_for_item` -- both the primary path and its `except` fallback.
  - The `except Exception:` producer tail in `engine.stream_producer` (one sink for all three providers). This one bypasses the terminal ladder entirely: the client helpers raise with a raw slice of the body in the message, so the tail is the ONLY thing standing between that body and the client. It carries a 800-cap scrub comment saying so -- keep it when you touch the tail.
  - `server_routes` non-stream catch-all (that file's own doc covers it).
  - Outside the set: browser/driver text rather than a completion body. NOT scrubbed today, both in `providers/deepseek/auth.py`: the no-token real-browser fallback logs a `(detail or "")[:200]` slice at info, and two driver-exception `logger.debug` lines (cookie-banner click, real-browser unavailable) log the raw exception. The login-page `_collapse(body, N)` diagnostics DO scrub before logging (wrapped in `scrub_upstream_text`), and `providers/qwen/auth.py::login_with_expiry`'s `except Exception` fallback logs `scrub_upstream_text(exc, 300)` - its raw `str(exc)` is the RETURNED detail, never a log. Do not widen a claim to cover the unscrubbed lines without scrubbing them first.
- `_BUFFERED_PRODUCER_READS = 3`. `stream_mode: buffered` sizes its watchdog against the whole producer budget (setup plus one full recovery pass), because the producer emits nothing until the reply lands. Live mode passes `False` and keeps the single-read budget once a payload has arrived, since every delta resets the clock. Both modes WIDEN the first `get`: `drain_stream_queue` waits `consumer_timeout × _BUFFERED_PRODUCER_READS` until the first payload (no mode has one yet, and the producer runs the same session + PoW + recovery work), so buffered's first-event budget is 9 reads and live's is 3 — after that the 3-read and 1-read budgets apply.
- `current_cancel_event()` publishes the token `drain_attempt` is draining under, thread-locally, for the length of the drain (restored, not cleared). A stream function sits inside a BLOCKING socket read, where returning control to `drain_attempt`'s per-event check is the only way a disconnect is ever noticed. It is thread-local rather than a parameter because every provider's `stream_fn` is `(headers, payload)`: a third positional would have landed in Qwen's `timeout`. Both web providers read it through `transport._cancellable(resp)` right after the POST, which swaps the response queue for `_BoundedQueue` so every parked read (SSE pump, non-SSE body drain) re-enters every `_READ_SLICE_SECONDS` and raises `_ClientGone` once the token is set -- cancellation GRANULARITY only, curl still owns the whole `DEFAULT_TIMEOUT` and `_abandon` skips the close that would join curl's silent worker. DeepSeek re-exports the names (`client._cancellable` / `_BoundedQueue` / `_abandon` / `_ClientGone` / `_READ_SLICE_SECONDS`) because tests read them off `client`; never add a parameter its peers do not accept.
- One in-flight stream per account is `item.lock`, and ONLY a thread that still holds it may release it: `threading.Lock.release()` from a non-holder SUCCEEDS, so a blind release steals the lock from the request that acquired the account meanwhile -- a third request could then stream on an account already in flight. `slot_releaser` publishes its give-up thread-locally (`_SLOT_ABANDONED`, read through `consume_slot_abandoned(item)`, identity-matched and consumed) on its three no-reacquire exits (cancel, deadline, acquire raising) and skips its own entry release after a give-up; every `run_with_failover` release site goes through `_release_slot`, so route new sites through it. The skip also drops the `uses` bump and the `_SLOT_COND` wake (a waiter is delayed at most one `_POLL_INTERVAL`, never stuck). `server_routes`' two direct `AccountPool.release(item)` calls fire right after a successful acquire, so they stay outside this contract.
- `_KEEPALIVE_INTERVAL` (15 s) / `_KEEPALIVE_FRAME` (`: ping\n\n`): `drain_stream_queue` slices its waits and pings a silent producer, because nginx drops an idle SSE body at 60 s and Cloudflare at 100 s -- a healthy slow reply died without even an error frame. A slice never crosses the budget, so a sub-interval `consumer_timeout` stays byte-identical, and `got_first` is set only by a real payload, never a ping.
- `registry._BUILTIN_MODULES` is the single registration point. Adding a built-in provider is one line there, never a caller-side import.
- `_LOADED` is set after the imports, never before, under `_LOAD_LOCK`, so a reader cannot observe a half-populated registry while the warmup daemon thread is still importing. `_REGISTRY` is updated in place, never rebound; callers and tests hold the dict itself.
- `deepseek` must stay in `_BUILTIN_MODULES`: `default()` and `resolved_ids()` fall back to it by name.
- `resolve_model` guards `provider.model_spec` in a try/except and skips a provider that raises, like its two sibling call sites (`build_models_list`, `catalogue_tuples_for`) already did. It is also order-INDEPENDENT: a provider whose catalogue actually LISTS the model always wins, and a synthesised passthrough spec (opencode's `provider/model` form) is only returned when no provider in the set lists the id. Without that, a `providers` list with opencode first let its slash-passthrough swallow every model id containing a slash.
- A provider module that fails to import is logged and skipped, never raised. One broken optional provider cannot take the server down.
- `openai.py` resolves the tool parser through a soft `sys.modules` lookup so a monkeypatched `zourcewell.server.parse_tool_calls` still wins; an explicit `parse_fn` overrides both. Keep the lookup.
- `tokens.extract_token` accepts raw text, JSON, double-encoded JSON, and the literal `{"value": null}` shape, returning the usable value or `""`. `{"value": null}` normalizes to "missing token" instead of causing a later upstream 40003.
- `browser_paths` never resolves a CWD-relative binary: `_candidates()`, `discover_browser` and `resolve_browser` all filter through `_anchored` (a non-empty `Path.anchor`, deliberately not `Path.is_absolute()`, which is False for a POSIX candidate like `/usr/bin/google-chrome` on Windows). An unset `LOCALAPPDATA`/`PROGRAMFILES` makes `Path("") == Path(".")`, and a `PATH` entry of `.` does the same for `shutil.which` -- without the filter, login launches a binary planted in the working directory and types the account's credentials into it.
- `ObscuraBridge.cookie_header(names=...)` filters the shared jar to a name allowlist; `None` ships every cookie (the historical behavior). The jar belongs to ONE upstream's WAF session, so a per-upstream caller passes its own names instead of handing its host cookies that host never issued (no production caller yet).

## Work Guidance

- Put shared behavior here only once a second provider needs it. Anything one provider uses alone stays in that provider.
- Keep transport free of retry codes, ban classification and string matching. Those are provider decisions; transport moves bytes and classifies HTTP status.
- `pools.py` late-imports `..accounts` inside functions so it never enters an import cycle. `pools.active_provider_ids` does NOT consult the registry — it reports what the config says, and `config.load_settings` is where an unknown id is rejected, so the two must not both second-guess the operator.
